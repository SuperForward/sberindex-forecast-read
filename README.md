# SberIndex Terminal

Прогноз безналичных потребительских расходов в муниципалитетах России и раннее
обнаружение структурных сдвигов (шоков) на данных СберИндекса.

**Что получилось** (цифры на 9 октября 2026 г.; приложение само подтягивает свежие данные, и позже его цифры могут отличаться)

- Прогноз расходов на жителя для 2 190 территорий набора (2 189 муниципальных
  образований, МО: один округ записан двумя кодами) на 1, 3, 6 и 12 месяцев. Итоговая модель считает простое среднее 14 моделей: средняя ошибка
  842 ₽ на жителя в месяц против 1 481 ₽ у Prophet (на 43% меньше). Точнее
  Prophet на всех четырёх горизонтах, на 45–61%.
- Сравнение 12 детекторов сдвигов при одинаковой доле ложных тревог. Лучшим
  оказался EWMA по общему и категорийным сигналам: 42% искусственных сдвигов при 5% ложных
  тревог, почти без задержки.
- Новости Lenta.ru, события GDELT и акты о ЧС привязаны к МО и месяцу по дате
  публикации: новость о шоке приходит на месяц раньше данных и объясняет тревогу
  детектора.
- Готовые нейросети для временных рядов (Chronos-Bolt, TimesFM 2.5) участвуют
  и в сравнении, и в итоговом среднем.

## Быстрый старт на новом ПК

Нужны Windows 10/11 и Python 3.12 (https://www.python.org/downloads/, отметить «Add to PATH»).

```powershell
git clone <адрес репозитория>
cd sberindex-forecast
powershell -ExecutionPolicy Bypass -File setup.ps1
.venv\Scripts\python -m app.main
```

`setup.ps1` создаёт `.venv`, ставит точные версии библиотек из
`requirements.lock.txt` и, если данных ещё нет, скачивает снимок данных
(адрес задан в `configs/pipeline.yaml` → `snapshot.url`). Без консоли приложение
запускается двойным кликом по `run_app.vbs`. Закрыть из консоли (штатно, со значком в трее): `.venv\Scripts\python -m app.main --quit`. DevTools: `Ctrl+Shift+I`,
remote debug: `--debug` (порт 9222).

Все пути в коде и конфигах указаны относительно корня проекта, папка может лежать где угодно.

Linux / macOS: `bash setup.sh`, затем `.venv/bin/python -m app.main`. Основная
платформа: Windows 10/11; уведомления и задача планировщика есть только там;
на Linux/macOS расписание настраивается через cron: `0 * * * * cd <проект> && .venv/bin/python -m worker run`.

Если что-то не устанавливается: полный вывод установки лежит в `logs/setup.log`.
Частые причины и что делать:

| симптом | причина | решение |
|---|---|---|
| «Путь к папке проекта слишком длинный» | ограничение Windows 260 символов | перенести проект ближе к корню (`C:\sberindex-forecast`) |
| «Нет прав на запись в папку проекта» | проект в `Program Files` | скопировать в свою папку |
| предупреждение про кириллицу в пути | движок Prophet не любит не-ASCII пути | перенести в папку с латинским именем |
| окно без содержимого / чёрное (виртуальная машина, RDP) | нет аппаратного ускорения | запустить с `--software` |

## Как повторить результаты

Три команды в PowerShell из корня проекта, после `git clone`:

```powershell
powershell -ExecutionPolicy Bypass -File setup.ps1
.venv\Scripts\python -m pip install -r requirements-dev.txt; .venv\Scripts\python -m pytest -q
.venv\Scripts\python -m worker run --force --heavy
```

1. Создаётся `.venv`, ставятся точные версии библиотек и скачивается снимок данных.
2. 75 тестов (около 4 минут) проверяют данные, модели, интервалы, детектор сдвигов и сервер.
3. Пересчитывается весь конвейер, включая горизонты 6 и 12 месяцев, и результаты публикуются в `data/sberindex.duckdb`.

Результаты после пересчёта: таблицы в `reports/backtest/models/metrics.md` и `reports/cpd/`,
отчёт `docs/report.md`, приложение (`python -m app.main`) и разделы «Модели» и «Сдвиги».
Снимок содержит готовые данные, поэтому модели пересчитываются по ним. Чтобы пересобрать и сами
данные из исходных выгрузок, снимок нужно собрать с исходниками (`worker snapshot pack --raw`, см. ниже).
Параметры моделей и сиды заданы в `configs/*.yaml`.

## Веб-версия

Тот же интерфейс в браузере, три способа:

| режим | запуск | для чего |
|---|---|---|
| настольное приложение | `.venv\Scripts\python -m app.main` | работа: трей, уведомления, пересчёт; страница итогов («← Итоги») та же, что в веб-версии |
| веб-сервер (REST API) | `.venv\Scripts\python -m server` → http://127.0.0.1:8000, описание API на `/docs` | браузер на своём ПК; `--allow-write` разрешает пересчёт |
| статическая сборка | `.venv\Scripts\python -m scripts.build_static` → `dist/web/` | публичная демо-версия (GitHub Pages): только чтение, без сервера |
| Docker | `docker compose up --build` | сервер + воркер одной командой, без установки Python |

Публикация демо-версии: сценарий `.github/workflows/pages.yml`
(Actions → pages → Run workflow) собирает статическую версию из последнего
релиза и выкладывает на GitHub Pages (Settings → Pages → Source: GitHub
Actions). Посмотреть у себя: `python -m http.server 8000 -d dist/web`. Сервера в
интернете нет, только файлы; кнопок пересчёта в демо нет.

## Данные, воркер и пересчёт

Результаты публикуются в `data/sberindex.duckdb` (приложение читает оттуда),
журнал запусков в `data/state.sqlite`, логи шагов в `logs/worker/`.
Шаги, их входы и выходы описаны в `configs/pipeline.yaml`.

```powershell
.venv\Scripts\python -m worker status          # что устарело, последние запуски
.venv\Scripts\python -m worker run             # пересчитать изменившееся
.venv\Scripts\python -m worker run --fetch     # сначала скачать свежие данные
.venv\Scripts\python -m worker run --force     # пересчитать всё
.venv\Scripts\python -m worker run --heavy     # включая горизонты (~35 мин)
.venv\Scripts\python -m worker loop            # работать по расписанию
.venv\Scripts\python -m worker install-task    # запускать воркер при входе в Windows
```

То же можно сделать кнопками в разделе «Данные» приложения; после фонового пересчёта
приложение само подтягивает новые результаты.

- Шаг пересчитывается, только если изменились его входные файлы, код или конфиг.
- Если шаг упал или данные не прошли проверку качества (`quality` в
  `configs/pipeline.yaml`), всё возвращается к последним хорошим результатам.
- Два пересчёта одновременно не идут (блокировка ОС).
- Скачиваются автоматически (проверка каждые 6 ч, у каждого источника свой
  интервал `every_h`): курсы ЦБ раз в 6 ч, погода раз в 7 дней, вакансии «Работы
  России» раз в неделю, ЕМИСС, вклады ЦБ и БД ПМО Росстата раз в месяц. Периоды
  считаются от текущей даты. Файл перезаписывается, только если данные
  изменились, поэтому модели не пересчитываются впустую.
- У выгрузки СберИндекса по МО, xlsx Росстата и ручных выгрузок ЕМИСС нет
  устойчивых адресов: новый файл достаточно положить в `data/raw/`, воркер
  заметит его и пересчитает.
- Дашборды СберИндекса по России (sberindex.ru/ru/dashboards, «Потребители»:
  расходы, рост г/г, индекс с сезонной корректировкой) скачиваются кнопкой
  CSV на странице дашборда и кладутся в `data/raw/sberindex/`.
- Приложение само запускает обновление: при старте (данные могли выйти, пока
  оно было закрыто) и раз в минуту, пока открыто.

### Снимок данных для GitHub Release

```powershell
.venv\Scripts\python -m worker snapshot pack          # dist/sberindex-data.zip + .sha256
.venv\Scripts\python -m worker snapshot pack --raw    # ещё исходники (~200 МБ)
.venv\Scripts\python -m worker snapshot fetch --url <адрес архива>
```

Архив и файл `.sha256` прикладываются к релизу, адрес архива прописывается
в `snapshot.url`. При скачивании проверяется контрольная сумма, распаковка
пишет только в `data/` и `reports/`.

## Прогноз: сравнение моделей

```bash
.venv/Scripts/python -m scripts.run_backtest --config models
```

Результаты в `reports/backtest/models/`: `metrics.md` (MAE, WAPE, R² по
горизонтам и окнам), `error_correlation.csv` (насколько похожи ошибки
моделей), `ensembles.csv` (выигрыш ансамблей по парам),
`rolling_selection.csv` (скользящая проверка способов собрать прогноз из
моделей: среднее всех, жадный выбор, лучшая по прошлому) и
`interval_coverage.csv` (покрытие интервалов 80%). Главная модель:
`mean_all`, среднее всех моделей без подбора состава. Они же
показываются в разделе «Прогноз» приложения.

## Прогноз: горизонты 1, 3, 6, 12 месяцев

```bash
.venv/Scripts/python -m scripts.run_horizons --config horizons
```

Все горизонты проверяются на одних и тех же целевых месяцах (07–12.2024):
для горизонта H прогноз строится из месяца «цель − H», берётся H-й шаг.
Если модели не хватает истории (глобальные модели и baseline на 12 мес.),
в таблице «н/д». Для 6 и 12 мес. есть модель «тот же месяц год назад × рост
по России» (`national_growth`): общероссийский рост г/г берётся из дашборда
СберИндекса (`data/raw/sberindex/consumer-spending-growth_*.csv`, с 2018 г.).
Результаты в `reports/horizons/`, раздел «Модели».
Prophet на всех МО считается около получаса.

## Структурные сдвиги: сравнение детекторов

```bash
.venv/Scripts/python -m scripts.run_cpd --config cpd
```

Детекторы работают с «локальным ростом»: рост МО к тому же месяцу прошлого
года минус медианный рост по всем МО, в единицах обычного разброса МО.
Качество меряется на синтетических сдвигах −5/−10/−15%, порог каждого метода
подобран под одинаковую долю ложных тревог (5% МО за год), затем лучший
метод проверяется на паводках апреля 2024 г. Результаты в `reports/cpd/`,
раздел «Сдвиги».

### Ручные выгрузки ЕМИСС

Автоматически fedstat.ru отдаёт только срез по умолчанию (часто 1–2 года).
Выгрузка с выбранными фильтрами делается только со страницы показателя,
поэтому длинные ряды скачиваются вручную: на странице показателя выбрать годы (с `year_from`
в `configs/extra_sources.yaml` по текущий), все субъекты, все периоды,
затем «Скачать» → SDMX. Файл положить как `data/raw/emiss/<id>_<name>.xml`:
ручной файл важнее автоматического `.xml.gz` и не перезаписывается.
`scripts.build_extra` пишет в `logs/data.log`, какие ряды короткие или устарели.

| файл | показатель | что выбрать |
|---|---|---|
| [57039_income_per_capita.xml](https://fedstat.ru/indicator/57039) | среднедушевые денежные доходы | 2010–, кварталы |
| [59577_poverty_rate.xml](https://fedstat.ru/indicator/59577) | уровень бедности | все годы, все субъекты |
| [43418_unemployment_registered.xml](https://fedstat.ru/indicator/43418) | регистрируемая безработица | 2013–, месяцы (сейчас кончается 2022) |
| [43062_unemployment_ilo.xml](https://fedstat.ru/indicator/43062) | безработица по МОТ | до текущего квартала (сейчас кончается 2023) |
| [31052_basket_cost.xml](https://fedstat.ru/indicator/31052) | стоимость фиксированного набора | 2017–, месяцы |
| [31448_prices_fuel_utilities.xml](https://fedstat.ru/indicator/31448) | цены на бензин, дизель, проезд, ЖКУ | 2017–, товары из `keep` |
| [31452_housing_price_m2.xml](https://fedstat.ru/indicator/31452) | цена 1 м² жилья | 2010–, все типы квартир, все субъекты |
| [42861_loans_households.xml](https://fedstat.ru/indicator/42861) | кредиты физлицам | 2017–, в рублях |
| [39619_loans_sme.xml](https://fedstat.ru/indicator/39619) | кредиты МСП и ИП | 2017–, в рублях |
| [63384_loans_corporate.xml](https://fedstat.ru/indicator/63384) | кредиты юрлиц и ИП | все годы, итого, все субъекты |

Список файлов с контрольными суммами лежит в `data/raw/MANIFEST.csv` (входит в снимок).
